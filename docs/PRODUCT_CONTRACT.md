# Eneye 产品契约（v0.2）

本文件是 Eneye 的行为合同。实现可以重构，但未经明确的产品决策，不得降低这里的保证。验收以本文件、失败矩阵和真实运行证据为准，不以“某个样例修好了”为准。

## 1. 产品目标与非目标

Eneye 是 Windows 上的跨应用悬停词典与 AI 翻译器。它读取当前屏幕可见文字，在用户悬停或拖选后给出可解释的结果。

**目标**

- 准确率优先：宁可暂时不出卡，也不显示错误 headword。
- 每个结果都能追溯：鼠标下是哪段可见文字、哪个 provider、原始 token、词框、来源窗口、为什么选中或隐藏。
- 同一套行为覆盖浏览器、PDF、记事本、Office、图片与扫描件。
- 词典、AI、悬浮窗、诊断各自有可复现的端到端验收。

**非目标**

- 不索引磁盘文件，不读取屏幕外内容。
- 不自动上传截图或上下文，不实现遥测、云同步、自动更新。
- 不绕过 DRM、管理员权限或系统安全边界。
- 不把用户私人的阅读内容或受限词典文件提交为公开 fixture。

## 2. 不可破坏的既有能力

以下能力在 v0.2 中必须继续工作：

- 鼠标稳定悬停自动查词。
- 拖选文字自动 AI 翻译。
- 内置 ECDICT。
- 外部 CSV、MDX/MDD、StarDict 词典。
- 本地生词本、查询历史、诊断。
- Windows Credential Manager 保存 API Key。
- 托盘、全局快捷键、无焦点悬浮窗。
- 不自动上传截图，不实现遥测。

技术栈保持 Tauri 2 + Rust + React/TypeScript。取词重构不得重做整个视觉层。

## 3. 统一取词契约

### 3.1 输入与拒绝

一次取词请求至少包含：

```text
pointer: physical screen (x, y)
sourceWindow: hwnd, pid, title, class, process path
modifiers: none
```

以下情况必须拒绝，不产生单词卡：

- 指针在 Eneye 自己的窗口、托盘、设置窗、悬浮卡内。
- 指针在截图/录屏工具覆盖层或已知的截图区域。
- 指针下没有可见文字，只有空白、题号、选项标记、下划线、引号或纯标点。
- 目标窗口属于 Eneye 自身进程，或属于系统安全界面。
- 文字无法证明视觉完整（见 3.4）。

### 3.2 Provider 与候选

所有 provider 返回同一种候选结构，不允许“谁先返回就用谁”：

```text
provider             uia | msaa | win32 | ocr-normal | ocr-denoised
rawText              该 provider 直接读到的原始文本
headword             归一化后的候选词
bounds               physical screen rect
sourceWindow         hwnd / pid / title / class
pointerInside        指针是否落在候选词框内（含容差）
pointerOnLetter      指针是否落在字母墨迹上
visualCompleteness   complete | prefix | suffix | broken | unknown
confidence           0..1
durationMs           provider 自身耗时
reason               可读的选择/拒绝原因
evidence             dictionaryHit, frequency, collins, oxford, ...
```

UIA、MSAA、Win32、OCR 必须相互校验。可访问文本只能证明“这里有一段文字”，不能单独证明“这段文字就是完整单词”。

### 3.3 归一化

- 统一大小写、去除首尾标点和下划线、折叠空白。
- 保留合法的内部连字符与撇号。
- 不把题号、选项字母、引号、括号、下划线并入 headword。
- OCR 的数字/字母混淆只能在“有词形证据、且不改变可见字母数量”时修复；不得凭空合成词典词。
- 最终 headword 必须能由原始 token 和可见墨迹解释。

### 3.4 视觉完整性

一个候选只有在下列条件同时成立时，才可作为完整单词提交：

1. 指针落在候选词框内，且落在字母墨迹附近。
2. 词框左侧、右侧没有属于同一词的连续字母墨迹。
3. 词框没有跨越明显的行边界或列边界。
4. 候选不是仅由标点、数字或单字母题号组成。
5. 候选的 letter count 与词框宽度、字体高度在合理比例内。
6. 若视觉无法证明完整，返回“未知/不完整”，隐藏卡片并写入诊断。

OCR 必须至少生成正常版与去干扰版两组结果。正常版用于可读文本，去干扰版用于下划线、引号、反色、低对比度等场景。两组结果不得互相覆盖对方的证据。

### 3.5 选择与置信度

- 先收集所有候选，再做归一化、完整性校验、评分和选择。
- 词典命中是证据，不是视觉完整性的证明。
- 不允许使用“最后一个候选”兜底。
- 不允许为了某个样例写字符串特判。
- 同等条件下，优先视觉完整、来源窗口可信、词典证据更强、编辑距离更小的候选。
- 最终显示必须给出 confidence 和 reason；低于产品阈值时隐藏。

### 3.6 稳定与抖动

- 指针在同一词内的轻微抖动（不超过产品稳定半径）不得重复查询或反复开关卡片。
- 指针真正移动到另一个词时，先更新 anchor，再允许新查询。
- 卡片打开后，指针进入卡片区域不得触发新取词；离开卡片后按 linger 设置处理。

## 4. 应用与环境矩阵

必须实测以下组合，而不是只测一个浏览器页面：

| 场景 | 必测内容 |
| --- | --- |
| Windows 记事本 | 纯文本、光标、换行、未保存文档、任意字母位置 |
| Chrome / Edge | 普通网页、带引号/括号/下划线文本、滚动后 |
| Calibre | 阅读器正文、分页、选中文字 |
| PDF 文本层 | 正常字号、缩略图、滚动、跨行 |
| 扫描 PDF / PNG | OCR、低对比度、倾斜、下划线 |
| Office / WordPad | 文本框、表格、不同字号 |
| DPI | 100% / 150% / 200% |
| 显示器 | 主屏、负坐标副屏、右/下边缘 |

硬验收：

- 记事本 `pollution` 的任意字母位置都返回 `pollution`，不能返回 `poll` 或 `on`。
- `A)As being` 返回 `being` 或 `As`，不返回 `AAsbelng`。
- `war on pollution` 不拆成 `wa/r`、`0/n`。
- 空白、题号、下划线、标点不出单词卡。
- 真正独立的 `poll`、`on` 仍正常。
- curated 回归集 top-1 准确率至少 98%，虚构 headword 为 0。
- OCR 首卡 p95 ≤ 1.2s，最差 ≤ 2.5s；无法满足时宁可隐藏，不得为速度回到错误短词。

## 5. 词典契约

### 5.1 格式矩阵

| 格式 | 必须支持 | 说明 |
| --- | --- | --- |
| CSV / TSV | word + translation；可选 phonetic、pos | 纯文本 fallback 必须可读 |
| MDX / MDD | MDX 主词条；MDD 图片/音频从同目录关联 | 不支持格式要说明原因 |
| StarDict | ifo/idx/dict/dz/syn 成套识别 | 同目录多套词典要能选择 |

导入体验：

- 选择一套词典时自动识别同目录配套文件，不要求用户猜 `.mdx` 还是 `.mdd`。
- 文件移动后提供重新定位，不只提供删除。
- 设置页显示格式、词条可用状态和测试查询按钮。
- 不允许“导入成功但查询空白”且不给原因。

### 5.2 重定向

- 支持 `@@@LINK=...`、大小写、变形词、循环检测和最大深度。
- 可解析时必须显示目标词义，不能把 `@@@LINK=make` 当正文。
- 目标缺失时显示“重定向目标不存在”，不能裸露控制字符串。
- 同一目标重复出现时去重。

### 5.3 折叠与展示

- 多词典之间默认显示词典级折叠框。
- HTML 词典识别出 senses 时，每个义项有独立折叠框。
- 无法结构化解析的 HTML 至少提供“完整释义”折叠框。
- CSV 纯文本至少按词性/行显示，不能出现空白卡片。
- 折叠状态、滚动、MDD 图片、发音和键盘操作必须可用。

真实导入验收：CSV、MDX/MDD、StarDict 至少各一个 fixture；导入、查询、排序、移除、重启后恢复全部通过。现有 OALD `makes → make`、`autonomy` 双音标不得回归。

## 6. AI 契约

### 6.1 配置与可用状态

- Base URL、协议（OpenAI Chat Completions / Anthropic Messages）、API Key、模型。
- “测试连接并读取模型”必须返回明确状态；`/models` 不可用时允许手动输入模型名称。
- API Key 只进 Windows Credential Manager，不写设置文件、日志、诊断或交付文件。
- 没有 Key 或模型时，UI 必须明确显示“AI 尚未配置”，不得像已可用。
- 模型、协议、Key 的变更必须影响下一次请求，不依赖重启。

### 6.2 翻译与解释分流

- “翻译”使用翻译提示词，只输出译文。
- “用 AI 解释未收录词”使用解释提示词，输出释义/用法，不能复用翻译引擎后假装解释。
- 两者使用不同 request kind，事件与历史记录可区分。

### 6.3 流式链路

- 拖选英文/中文后自动翻译，卡片显示原文、流式译文、取消、关闭、复制、重试。
- 两个开关门禁不同：「启用 AI 翻译」是总开关，关闭后拖选、Ctrl+Alt+T、卡片里的 AI 解释全部停用；「自动翻译选区」只约束拖选后自动弹译文，关掉它之后 Ctrl+Alt+T 和卡片内的 AI 解释仍然可用。
- 新翻译必须取消旧请求；旧请求的 delta/completed 不得覆盖新卡。
- 取消是正常终态，不得显示为错误或“重试”状态。
- 202、204、非流式 2xx、401/403、404、429、5xx、超时、断流、空响应、畸形 JSON 都有明确错误文案。
- 翻译成功后写历史；取消和失败不能写伪成功记录。
- AI 译文卡片手动关闭，不因鼠标离开自动消失。

验收：

1. 本地 mock server 端到端：测试连接、模型列表、拖选、流式、取消、断流、重试。
2. 真实 Key 可选：用户配置后测 DeepSeek/OpenAI/Anthropic 至少一个；Key 不写日志或交付文件。
3. 当前默认配置若无 Key/模型，UI 明确显示未配置。

## 7. 悬浮窗契约

- 使用卡片真实 measured bounds，不使用固定 440×610 窗口猜位置。
- 水平偏移和垂直偏移分开，默认值合理。
- 距离范围至少 0–240px；从鼠标 hotspot 到卡片最近边的距离定义稳定。
- 滑块变化时，若卡片可见立即移动，不需要重新悬停。
- 屏幕右/下边缘翻转时仍保持同一逻辑距离。
- 多显示器、负坐标、不同 DPI 下一致。
- 设置页提供可拖动的实时位置预览。
- 卡片不得覆盖鼠标正下方原文，也不得在调整时跳动。

验收：

- 偏移 0、20、64、120、240 时，卡片到鼠标边缘实测距离与显示值误差 ≤ 4 physical px。
- 右边缘、下边缘、负坐标副屏都通过。
- 拖动滑块时卡片连续更新。

## 8. 诊断契约

诊断页至少展示：

- 真实鼠标坐标、显示器、DPI。
- UIA/MSAA/Win32/OCR 每层结果、耗时和失败原因。
- OCR crop、token、bounds、候选和分数。
- UIA/OCR 最终决策。
- 为什么显示或隐藏。
- 可提交“正确词”并保存本地纠正记录。

证据库：

- 自动测试之外，必须跑真实鼠标和桌面截图。
- 每个失败样例保存最小 fixture。
- 不使用用户私人内容或受限词典文件作为公开 fixture。
- 修复前后都有截图或诊断 JSON。

## 9. 架构边界

```text
input/        鼠标、拖选、窗口排除
probe/        UIA、MSAA、Win32、OCR provider
recognition/  候选归一化、完整性、评分、选择
dictionary/   格式读取、redirect、HTML senses、资源
overlay/      测量、定位、边缘翻转、锚点
translation/  API、stream、cancel、errors
diagnostics/  证据、耗时、用户纠正
```

`capture.rs` 只负责状态机和协调，不直接实现所有词边界启发式。

## 10. 发布门禁

以下全部通过才可宣布 v0.2 完成：

- `npm run verify`
- `cargo test --all-targets`
- `cargo clippy --all-targets -- -D warnings`
- `cargo fmt --all -- --check`
- release build
- 真实鼠标 + 实际安装版验收
- 安装包、commit hash、SHA-256、测试数量和真实证据

禁止：

- 围绕 `pollution/poll/on` 添加单独字符串规则。
- 把 `dictionary_hit` 当成视觉完整性的证明。
- 只用手写 OCR token 模拟所有真实场景。
- 用固定 440×610 窗口代表所有卡片尺寸。
- 把“测试连接”当作真正翻译验收。
- 导入成功但查询空白却不给原因。
- 没有真实鼠标和实际安装版证据时宣布完成。
